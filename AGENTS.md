# Notes for coding agents

`CLAUDE.md` is the source of truth for this repository: mission, non-negotiables,
architecture, performance rules and conventions. Read it first. This file only
adds the working rules that are easy to get wrong.

## Before you commit

- `make lint` and `make test` must pass. `make lint` is gofmt, `go vet`, a tidy
  `go.mod` and golangci-lint (`.golangci.yml`). CI runs the linter for
  linux/amd64, linux/arm64, darwin/arm64 and windows/amd64, so code behind build
  tags has to be clean on every one of them:
  `GOOS=linux GOARCH=amd64 golangci-lint run ./...`.
- `CGO_ENABLED=0 go build ./...` must succeed. No cgo, no new dependencies
  without a justification (see `CLAUDE.md`).
- Commit subjects are Conventional Commits, `type(scope): description`, with the
  package as the scope: `perf(gemm): …`, `feat(ops,graph): …`, `fix(kernels/metal): …`.
  Types: feat, fix, perf, docs, test, bench, refactor, build, ci, chore, style,
  revert. No trailing period, at most 100 characters. Run `make hooks` once per
  clone; CI rejects anything else, including PR titles.
- Performance commits state before/after numbers in the body.

## What never goes in the repository

This applies to code, comments, docs, test names, scripts and commit messages.

- The identity of any machine the work was measured or run on: model names,
  hosting providers, hostnames, core or thread counts that describe a specific
  box. Say "Apple Silicon", "a Zen 5 box", "an AVX2-only x86 box". CPU families
  are fine where they explain a kernel choice; the public CI runner is fine.
- Other projects, private repositories, private hosts, local paths.
- Model weights and anything derived from licence-bound weights or datasets.
  Reference activations and exported models are regenerated by `tools/export`
  and stay ignored under `testdata/`; only small synthetic corpora are committed.
- Build outputs, profiles, generated media. If a command writes a new kind of
  artifact, add it to `.gitignore` in the same change.

## Working alongside others

- Other sessions may be editing this tree at the same time. Do not commit, stage,
  revert or reformat files you did not change, and do not commit someone else's
  in-progress package.
- Do not rewrite published history or force-push unless explicitly asked.
- Releases are cut by pushing a `vX.Y.Z` tag on `canary`; do not tag unless asked.
